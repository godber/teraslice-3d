Chapter 05 · Foundation / URLSession

Networking

One actor, four endpoints, no dependencies. TerasliceAPIClient is a good model of modern async URLSession use — and a good case study in how a well-meant fallback strategy can hide failures from the user.

actor URLSession async/await URLRequest HTTPURLResponse Result App Transport Security

The four endpoints

MethodEndpointReturnsTimeout
fetchPipelineGraphGET /api/pipeline_graphResult<PipelineGraph, APIError>8 s
fetchJobsGET /api/jobs?size=500&active=true&ex=_statusResult<[JobDetails], APIError>8 s
clearCachePOST /api/cache/clearBool5 s
fetchVersionGET /api/versionString5 s

These match the FastAPI backend documented in the repo's CLAUDE.md, including the hard-coded size=500 job limit the web frontend also uses.

Why an actor

Sources/Services/TerasliceAPIClient.swiftlines 19–24
public actor TerasliceAPIClient {
    private let urlSession: URLSession

    public init(urlSession: URLSession = .shared) {
        self.urlSession = urlSession
    }
}

An actor is a reference type whose mutable state is protected by the compiler: only one task executes inside it at a time, and callers from outside must await. It's Swift's built-in answer to "put a lock around this object", with the lock checked at compile time rather than remembered by hand.

Strictly speaking this client holds no mutable state, so it doesn't need actor isolation — URLSession is already thread-safe. But it makes the type trivially Sendable, so passing it around under Swift 6 strict checking is free, and it's the right home for state you'd add later (a response cache, an in-flight request map, an auth token).

🟠
Swift note · dependency injection via a default argument

init(urlSession: URLSession = .shared) is the whole DI story. Production code calls TerasliceAPIClient(); a test can pass a session configured with URLProtocol stubs. The current test suite doesn't exercise this — it uses the isMock flag instead — but the seam is already there.

Anatomy of one request

Sources/Services/TerasliceAPIClient.swiftlines 26–58
public func fetchPipelineGraph(serverConfig: ServerConfig) async -> Result<PipelineGraph, APIError> {
    if serverConfig.isMock {
        return .success(MockGraphProvider.samplePipelineGraph())
    }

    guard let baseURL = serverConfig.baseURL,
          let url = URL(string: "/api/pipeline_graph", relativeTo: baseURL) else {
        return .failure(.invalidURL)
    }

    var request = URLRequest(url: url)
    request.timeoutInterval = 8.0
    request.setValue("application/json", forHTTPHeaderField: "Accept")

    do {
        let (data, response) = try await urlSession.data(for: request)
        guard let httpResponse = response as? HTTPURLResponse else {
            return .success(MockGraphProvider.samplePipelineGraph())
        }

        guard (200...299).contains(httpResponse.statusCode) else {
            return .failure(.serverError(statusCode: httpResponse.statusCode))
        }

        let graph = try JSONDecoder().decode(PipelineGraph.self, from: data)
        return .success(graph)
    } catch {
        // Fallback to mock data if network fails so app is immediately usable
        print("API fetch failed, falling back to mock data: \(error)")
        return .success(MockGraphProvider.samplePipelineGraph())
    }
}

Line by line, the framework pieces:

  • URL(string:relativeTo:) resolves /api/pipeline_graph against http://127.0.0.1:8000. The leading slash makes it root-relative, so any path on the base URL is replaced rather than appended. For anything more complex than this, URLComponents is the right tool — it also percent-encodes query values, which the hand-written "?size=500&active=true&ex=_status" string in fetchJobs gets away with only because those values happen to be URL-safe.
  • URLRequest carries the method, headers, body and per-request timeout. It's a struct, hence var request before mutating it.
  • try await urlSession.data(for:) is the async replacement for the completion-handler API. It returns a tuple (Data, URLResponse) and throws on transport failure. It also participates in cooperative cancellation: cancel the surrounding Task and the HTTP request is cancelled too.
  • response as? HTTPURLResponse — the generic URLResponse has no status code, so it's downcast conditionally. as? yields an optional; as! would crash on failure.
  • (200...299).contains(…) — a ClosedRange<Int> used as a set membership test. Idiomatic Swift for status-code checks.
  • do/catch around try — both the network call and the decode can throw, and both land in the same catch.

The fallback strategy, and why it will bite

Three different failure modes are handled three different ways, and two of them lie to the caller:

FailureCurrent behaviourWhat the user sees
Malformed base URL.failure(.invalidURL)AppState substitutes mock data
HTTP 4xx / 5xx.failure(.serverError)AppState substitutes mock data
Connection refused / timeout.success(mock data)Mock data, no error path taken at all
JSON that doesn't match the model.success(mock data)Mock data; the decode error only reaches print()
🔴
Gap · you cannot tell real data from fixtures

Every failure path ends at the same 9-node NOAA fixture, and AppState.refreshData() makes the .failure cases converge there too. Combined with fetchVersion returning the string "Offline Mode" on error, the only signal that your cluster is unreachable is a small label in the ornament — while a plausible-looking pipeline floats in front of you. For a monitoring tool, that's the wrong default: a failing production graph and a working fixture look identical.

The fix is small: let the client report failures honestly (throws, or Result with no mock substitution), keep AppState's last-known-good graph on error, and surface an explicit lastError in the ornament. Mock data then stays where it belongs — behind ServerConfig.isMock, which the user chooses deliberately from the server menu.

🪵
print() vs Logger

print goes nowhere useful on a device. The platform logging API is Logger from the os module: Logger(subsystem: "com.teraslice.Teraslice3D", category: "api").error("…"). It's structured, viewable in Console.app and log stream, privacy-aware, and nearly free when nobody is listening. Two of APIError's four cases (decodingError, networkError) are never actually constructed — they'd become useful the moment errors are propagated instead of swallowed.

Getting http://127.0.0.1:8000 to work at all

Apple platforms block plaintext HTTP by default via App Transport Security. This project takes the blunt route, in the Xcode build settings rather than a checked-in plist:

Teraslice3D.xcodeproj — generated Info.plist key—
GENERATE_INFOPLIST_KEY_NSAppTransportSecurity_NSAllowsArbitraryLoads = YES;

That allows all insecure loads. The narrower option is an NSExceptionDomains entry for 127.0.0.1 / localhost only, which is what you'd want before shipping. Two practical notes for running against a Mac-hosted backend:

  • Simulator: 127.0.0.1 resolves to the host Mac's loopback, so the default config works with fastapi dev running locally.
  • Real Vision Pro: loopback is the headset itself. Use the Mac's LAN address (http://192.168.x.x:8000) — exactly the case the "Add Custom Server" form in SettingsView exists for — and make sure the backend binds 0.0.0.0, not just localhost.

Things a production client would add

  • Retry with backoff for transient 5xx / timeouts, instead of waiting 30 s for the next poll.
  • A configured session — URLSession(configuration: .ephemeral) or a custom URLSessionConfiguration with waitsForConnectivity, cache policy and per-host limits, rather than .shared.
  • ETag / If-None-Match handling, since the graph rarely changes between 30-second polls.
  • Auth — the backend supports a custom CA (CACERT_FILE) and may sit behind a proxy; that means HTTPS plus either a pinned certificate via URLSessionDelegate or a trusted profile on the device.
  • Cancellation of superseded requests — switching servers mid-flight currently lets the old response land after the new one.
