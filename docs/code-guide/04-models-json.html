Chapter 04 · Foundation / Codable

Models & Codable

Four files, 387 lines, zero dependencies: how the backend's JSON becomes Swift values. This is also the best place in the codebase to learn Codable, because it contains one fully-synthesised model, one with a custom decoder, and one that decodes a nested payload.

Codable CodingKeys JSONDecoder nestedContainer Identifiable Sendable

The payload being modelled

The backend's /api/pipeline_graph returns the standard nodes-and-links shape that 3d-force-graph consumes on the web side, so the Swift models mirror the same JSON the browser gets:

GET /api/pipeline_graph (abridged)—
{
  "nodes": [
    { "id": "kafka_data3:incoming-noaa-isd-csv-v1", "connector_type": "KAFKA" },
    { "id": "es_data3:noaa-isd-v5-**",              "connector_type": "ES" }
  ],
  "links": [
    { "source": "kafka_data3:incoming-noaa-isd-csv-v1",
      "target": "es_data3:noaa-isd-v5-**",
      "job_id": "71e871d4-…", "name": "noaa-isd-store-es",
      "workers": 12, "status": "running",
      "url": "…", "grafana_url": null }
  ]
}

Level 1 — synthesised conformance

PipelineGraph is the easy case. Both properties are Codable, so the compiler writes the whole implementation:

Sources/Models/GraphData.swiftlines 101–108
public struct PipelineGraph: Codable, Equatable, Hashable, Sendable {
    public let nodes: [GraphNode]
    public let links: [GraphLink]

    public init(nodes: [GraphNode] = [], links: [GraphLink] = []) {
        self.nodes = nodes
        self.links = links
    }
}

Two details that are easy to miss:

  • Default parameter values (= []) mean PipelineGraph(), PipelineGraph(nodes: x) and the two-argument form all work from one initialiser. Swift has no overload explosion problem here.
  • Equatable is load-bearing. .onChange(of: appState.graphData) in PipelineVolumeView only fires when the value actually differs, and that comparison walks every node and link. Cheap for dozens of nodes; something to watch if a cluster ever returns thousands.
🟠
Swift note · writing your own init keeps the memberwise one

A struct gets a memberwise initialiser for free, but declaring init inside the type replaces it. The explicit public init here exists partly because the free one is internal — a public struct does not get a public memberwise init. (Declaring your own init in an extension instead would preserve the synthesised one.)

Level 2 — CodingKeys and a custom decoder

Sources/Models/GraphData.swiftlines 25–53
public struct GraphNode: Identifiable, Codable, Hashable, Sendable {
    public let id: String
    public let connectorType: ConnectorType

    public var isIncoming: Bool {
        id.lowercased().contains("incoming") || connectorType == .kafkaIncoming
    }

    enum CodingKeys: String, CodingKey {
        case id
        case connectorType = "connector_type"      // Swift name ⇄ JSON name
    }

    public init(from decoder: Decoder) throws {
        let container = try decoder.container(keyedBy: CodingKeys.self)
        self.id = try container.decode(String.self, forKey: .id)
        let rawType = try container.decodeIfPresent(String.self, forKey: .connectorType) ?? ""

        if id.lowercased().contains("incoming") && (rawType == "KAFKA" || rawType.isEmpty) {
            self.connectorType = .kafkaIncoming            // ← derived, not received
        } else {
            self.connectorType = ConnectorType(rawValue: rawType) ?? .unknown
        }
    }
}

The mechanics, in order:

  1. CodingKeys is a nested enum conforming to CodingKey. Its raw values are the JSON key names. Its cases must cover every property you want coded — omit a property's case and the synthesised code ignores that property entirely. (Note isIncoming is computed, so it's never coded regardless.)
  2. decoder.container(keyedBy:) gets a typed view of the JSON object. decode(_:forKey:) throws if the key is missing or the type is wrong; decodeIfPresent returns an optional instead.
  3. Business logic in the decoder. The backend sends "KAFKA" for both incoming and internal topics; the distinction — which drives the yellow-vs-blue colouring — is inferred from the substring "incoming" in the node id. This mirrors the documented quirk in the project's CLAUDE.md ("Special handling for connectors/topics containing 'incoming'").
  4. ConnectorType(rawValue:) ?? .unknown — an unrecognised connector type degrades to a grey sphere instead of throwing. Good instinct for a client that must tolerate a newer backend.
💡
The shortcut this code chose not to take

For pure snake_case-to-camelCase mapping you can skip CodingKeys altogether: decoder.keyDecodingStrategy = .convertFromSnakeCase. GraphLink takes a third route — its properties are named job_id and grafana_url so no mapping is needed at all. Three strategies in one folder; for consistency, most codebases pick the decoder strategy plus camelCase properties and never write CodingKeys unless the shape genuinely differs.

GraphLink: a computed id, and asymmetric coding

Sources/Models/GraphData.swiftlines 57–77
public struct GraphLink: Identifiable, Codable, Hashable, Sendable {
    public var id: String { job_id + "_" + source + "_" + target }
    public let source: String
    public let target: String
    public let job_id: String
    public let name: String
    public let url: String?
    public let workers: Int
    public let status: String
    public let grafana_url: String?

    enum CodingKeys: String, CodingKey {
        case source, target, job_id, name, url, workers, status, grafana_url
    }
}
  • No id case in CodingKeys — correct, since id is computed. The composite id matters because Teraslice's routed_sender lets one job fan out to several destinations, so job_id alone isn't unique among links.
  • String? for url and grafana_url — optional properties decode a missing key or explicit null as nil without any extra code.
  • status: String, not JobStatus — the link keeps the raw string and converts at render time (LinkEntity.material(for:) does JobStatus(rawValue: status.lowercased()) ?? .unknown). Decoding straight into the enum would be stricter and would centralise the fallback; it would also make an unexpected status a decode failure unless you wrote a custom initialiser. Deliberate looseness at a network boundary.

Level 3 — reaching into nested JSON

Teraslice's /api/jobs response nests the execution status one level down, under ex._status. Swift's answer is a second CodingKey enum and a nested container:

Sources/Models/JobDetails.swiftlines 42–93 (condensed)
enum CodingKeys: String, CodingKey {
    case job_id, name, lifecycle, workers, assets
    case created = "_created"
    case updated = "_updated"
    case ex                              // the nested object
}

enum ExKeys: String, CodingKey {
    case status = "_status"
}

public init(from decoder: Decoder) throws {
    let container = try decoder.container(keyedBy: CodingKeys.self)
    self.job_id  = try container.decode(String.self, forKey: .job_id)
    self.name    = try container.decodeIfPresent(String.self, forKey: .name) ?? "Unnamed Job"
    self.workers = try container.decodeIfPresent(Int.self, forKey: .workers) ?? 1
    // …

    if let exContainer = try? container.nestedContainer(keyedBy: ExKeys.self, forKey: .ex),
       let rawStatus = try? exContainer.decodeIfPresent(String.self, forKey: .status) {
        self.status = JobStatus(rawValue: rawStatus.lowercased()) ?? .unknown
    } else {
        self.status = .unknown
    }
}

nestedContainer(keyedBy:forKey:) descends into ex and gives you a container keyed by a different enum. Note the defensive layering: try? on the container, try? on the value, ?? .unknown on the enum conversion, and a fallback else. A job with no execution record decodes fine as .unknown rather than failing the entire array.

🟠
Swift note · one bad element fails the whole array

JSONDecoder().decode([JobDetails].self, from: data) is all-or-nothing: a single malformed element throws and you lose every job. If that matters, the usual fix is a wrapper type that decodes each element with try? into [JobDetails?] and compacts the nils — worth knowing before a production cluster surprises you.

The hand-written encoder

JobDetails also implements encode(to:), rebuilding the nested ex object on the way out:

Sources/Models/JobDetails.swiftlines 95–107
public func encode(to encoder: Encoder) throws {
    var container = encoder.container(keyedBy: CodingKeys.self)
    try container.encode(job_id, forKey: .job_id)
    // …
    var exContainer = container.nestedContainer(keyedBy: ExKeys.self, forKey: .ex)
    try exContainer.encode(status.rawValue, forKey: .status)
}

Nothing in the app encodes a JobDetails — the client only reads. It's there so the type round-trips, which is handy for snapshot fixtures and tests. Note var container: encoding containers are mutable structs.

ServerConfig: a value type with presets

Sources/Models/ServerConfig.swiftlines 4–31 (condensed)
public struct ServerConfig: Identifiable, Codable, Hashable, Sendable {
    public var id: UUID
    public var name: String
    public var baseURLString: String
    public var isMock: Bool

    public var baseURL: URL? {
        URL(string: baseURLString.trimmingCharacters(in: .whitespacesAndNewlines))
    }

    public init(id: UUID = UUID(), name: String, baseURLString: String, isMock: Bool = false) { … }

    public static let defaultLocal = ServerConfig(
        name: "Local FastAPI Backend",
        baseURLString: "http://127.0.0.1:8000",
        isMock: false)

    public static let mockDataServer = ServerConfig(
        name: "Offline Mock Data",
        baseURLString: "http://mock.internal",
        isMock: true)
}
  • id: UUID = UUID() — a fresh identity per instance by default, so ForEach and Picker can tell two configs apart even with identical names.
  • static let presets are the Swift idiom for named constants of a type. They're what makes .defaultLocal and .mockDataServer work with no type prefix at the use site.
  • baseURL: URL? is computed, so an invalid string simply yields nil and every caller must guard — see chapter 05.
  • Nothing persists these. Servers added in SettingsView live in memory only; relaunching restores the two presets. Codable conformance means adding persistence is a few lines with @AppStorage/UserDefaults + JSONEncoder, or SwiftData if you want more.

MockGraphProvider: fixtures as a first-class feature

MockGraphProvider is a namespace of two static functions returning a hand-built 9-node / 6-link graph and 6 matching job records, scrubbed from a real cluster (NOAA ISD weather data pipelines). It serves three distinct purposes:

  1. Initial state — AppState.graphData is initialised to it, so the very first frame draws a real graph instead of an empty volume.
  2. Offline mode — ServerConfig.mockDataServer has isMock = true and the API client short-circuits to it, which means you can develop the whole 3D layer in the simulator with no backend running.
  3. Test input — all nine XCTest cases feed on it (chapter 09).

The fixture is chosen with some care: it includes one stopped job, one failing job, a fan-out from a single Kafka topic to three Elasticsearch indices, and worker counts from 2 to 16 — enough to exercise every colour branch and the link-thickness scaling.

🟠
Swift note · struct as a namespace

public struct MockGraphProvider { public static func … } is never instantiated; it's a bag of static functions, the Swift equivalent of a module-level function group. Using a struct rather than a class means nobody can subclass it, and an enum with no cases (a "caseless enum") is the stricter version — it can't even be constructed by accident.
