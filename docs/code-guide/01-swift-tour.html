Chapter 01 · Language

Swift tour, by example

Every Swift language feature this codebase uses, in the order you'll trip over it, with the relevant chapter of The Swift Programming Language alongside. Nothing here is visionOS-specific — it is the vocabulary the next ten chapters assume.

Four kinds of type, and why each was chosen

Swift has several ways to declare a type, and this app happens to use all the interesting ones. The choice is not stylistic; it decides copying behaviour, identity, and thread safety.

KindSemanticsUsed here for
structValue type — copied on assignment, no identity, immutable unless varGraphNode, GraphLink, PipelineGraph, ServerConfig, Node3D, VolumetricProjection, and every SwiftUI View
classReference type — shared, has identity, ARC-managed, supports inheritanceAppState (one shared mutable model), ForceSimulation3D (mutated in place), and the RealityKit entities (they must subclass Entity)
enumClosed set of cases, optionally with raw valuesConnectorType, JobStatus, FilterMode, APIError
actorReference type that serialises access to its own stateTerasliceAPIClient
🟠
Swift note · the default is struct

Coming from Python or TypeScript, "everything is a class" is the habit to unlearn. In Swift, reach for struct until you need shared mutable identity. SwiftUI depends on this: views are cheap structs that get thrown away and rebuilt constantly, which is only sane because copying one is nearly free.

Properties: stored, computed, and lazily derived

Swift blurs the line between "field" and "method" deliberately. A computed property looks like data at the call site but runs code, which the models here use to derive values instead of storing them:

Sources/Models/GraphData.swiftlines 25–36
public struct GraphNode: Identifiable, Codable, Hashable, Sendable {
    public let id: String                        // stored, immutable
    public let connectorType: ConnectorType

    public var isIncoming: Bool {                // computed — no storage
        id.lowercased().contains("incoming") || connectorType == .kafkaIncoming
    }
}

Three details in seven lines:

  • let vs var is about mutability, not about storage. A computed property must be var because its value can change over time even though nothing is stored.
  • A single-expression body needs no return — the same implicit-return rule that makes SwiftUI view bodies readable.
  • .kafkaIncoming with no type prefix: Swift infers the enum from context. You'll see this everywhere, e.g. .zero for a SIMD3<Float> and .bottom for an ornament anchor.

GraphLink pushes the idea further — its id is not stored at all, it is synthesised from three other fields, which is what makes the link uniquely identifiable when one job writes to several destinations:

Sources/Models/GraphLink — GraphData.swiftline 58
public var id: String { job_id + "_" + source + "_" + target }
🟠
Swift note · naming

job_id and grafana_url are snake_case, which is not Swift style. They are named to match the backend JSON so the synthesised Codable conformance needs no mapping. The idiomatic alternative — camelCase properties plus explicit CodingKeys — is what GraphNode does for connector_type. Chapter 04 covers the trade-off.

Optionals, and the four ways this code unwraps them

T? means "a T or nothing", enforced by the compiler. There is no implicit null. Every unwrapping idiom in Swift shows up in this codebase:

Idioms collected from across Sources/—
// 1. guard let — early exit, keeps the happy path unindented
guard let baseURL = serverConfig.baseURL,
      let url = URL(string: "/api/pipeline_graph", relativeTo: baseURL) else {
    return .failure(.invalidURL)
}

// 2. if let — conditional branch
if let msg = cacheClearedMessage {
    Text(msg)
}

// 3. optional chaining + ?? default
try container.decodeIfPresent(Int.self, forKey: .workers) ?? 1
nodes[key]?.force = .zero          // no-op if the key is absent

// 4. try? — turn a thrown error into nil
if let exContainer = try? container.nestedContainer(keyedBy: ExKeys.self, forKey: .ex) { … }

The guard form is the one to internalise. It reads as a precondition, binds names for the rest of the scope, and forces you to write the failure path. Note that a single guard can chain several bindings separated by commas — the whole thing succeeds or the else runs.

🟠
Swift note · nodes[key]?.force = .zero

Dictionary subscripting returns an optional, so mutating through it needs a ?. This pattern appears dozens of times in ForceSimulation3D.tick() and it is quietly expensive: each write is a dictionary lookup plus a copy-on-write of the struct. Chapter 06 revisits it as the main performance smell in the layout engine.

Enums are where the domain logic lives

Swift enums are closed sets, so a switch over one is exhaustive — add a case and the compiler shows you every place that needs updating. This codebase uses them as small state machines with behaviour attached:

Sources/Models/JobDetails.swiftlines 4–28
public enum JobStatus: String, Codable, Sendable, CaseIterable {
    case running = "running"
    case starting = "starting"
    case stopped = "stopped"
    // …
    case unknown = "unknown"

    public var isFailingOrFailed: Bool {
        self == .failing || self == .failed
    }

    public var statusColorName: String {
        switch self {
        case .running: return "green"
        case .stopped, .stopping: return "orange"
        // …
        }
    }
}
  • : String gives each case a raw value, which is what makes JobStatus(rawValue: "running") work when decoding JSON. That initialiser is failable — it returns JobStatus? — hence the ?? .unknown you see at every call site.
  • CaseIterable synthesises allCases, used by ForEach(FilterMode.allCases) to build the segmented picker in the ornament.
  • An unknown case is defensive design: the backend can add a status without crashing the app.

APIError shows the other flavour — cases carrying associated values, which is Swift's answer to typed exceptions:

Sources/Services/TerasliceAPIClient.swiftlines 3–16
public enum APIError: Error, LocalizedError {
    case invalidURL
    case serverError(statusCode: Int)
    case decodingError(Error)
    case networkError(Error)

    public var errorDescription: String? {
        switch self {
        case .serverError(let code): return "Server returned error code \(code)."
        // …
        }
    }
}

case .serverError(let code) is pattern matching: it tests the case and pulls the payload out in one move. "…\(code)." is string interpolation. Conforming to LocalizedError is what makes error.localizedDescription produce your message instead of a generic one.

Protocols: the conformance list is the API

Swift leans on protocols where other languages use inheritance. When you read a declaration like struct GraphNode: Identifiable, Codable, Hashable, Sendable, each name buys a specific capability — mostly for free, via compiler synthesis:

ProtocolWhat it unlocksWhere it's needed
IdentifiableAn id property SwiftUI uses for diffingForEach(appState.jobs) with no id: argument
CodableSynthesised JSON encode/decodeJSONDecoder().decode(PipelineGraph.self, from: data)
Hashable== and hashing → usable as dictionary keys, Set members, and SwiftUI .tag() valuesPicker selection; .onChange(of: appState.graphData)
SendableCompiler-checked promise the value can cross concurrency domains safelyPassing graph data out of the actor API client
Equatable==.onChange needs it to know the graph changed

The synthesis is the part that feels like magic and isn't: if every stored property of a struct is itself Codable/Hashable/Sendable, the compiler writes the conformance for you. You only hand-write it when the shape of the data disagrees with the shape of your type — see JobDetails.init(from:) in chapter 04.

🟠
Swift note · some View

Every view here declares public var body: some View. some is an opaque return type: "one specific concrete type that conforms to View, and I'm not telling you which." It matters because SwiftUI view bodies have absurd generic types like VStack<TupleView<(Image, Text, …)>> — some View lets you avoid writing them while keeping full static dispatch. Same trick with some Scene in Teraslice3DApp.

Generics you'll meet without writing any

The app defines no generic types of its own, but consumes several. Recognising the notation is enough:

  • Result<PipelineGraph, APIError> — success-or-failure as a value rather than a thrown error. Consumed with switch result { case .success(let g): … case .failure: … }.
  • [String: Node3D] — sugar for Dictionary<String, Node3D>; [GraphLink] is Array<GraphLink>.
  • SIMD3<Float> — a three-lane vector of Float, hardware-accelerated. Chapter 06.
  • Task<Void, Never> — a unit of async work returning nothing and never throwing.
  • @Environment(AppState.self) — a metatype argument: the type itself passed as a value, which is how the environment is keyed.

Closures, trailing syntax, and result builders

Almost all SwiftUI and RealityKit code is closures with syntactic sugar on top. Three levels of the same idea:

Sugar levels, from plain Swift to SwiftUI DSL—
// A closure as a normal argument
Task(operation: { await refreshData() })

// Trailing closure — the last argument moves outside the parens
Task { await refreshData() }

// Two trailing closures, labelled (RealityView's make: and update:)
RealityView { content in
    content.add(graphEntity)
} update: { content in
    // …
}

// Result builder — statements in this closure are *collected*, not executed in order
VStack(spacing: 20) {
    Image(systemName: "cube.transparent.fill")
    Text("Teraslice 3D Volumetric Scene")
}

That last form is a result builder (@ViewBuilder). The closure body is not imperative code; the compiler rewrites the list of expressions into a single nested value. This is why you cannot drop an arbitrary for loop or print into a view body but can use if/switch and ForEach — the builder has overloads for those and nothing else.

🟠
Swift note · $0 and _

graph.nodes.first { $0.isIncoming } uses the implicit first-argument name. .onChange(of: graphData) { _, newValue in … } uses _ to discard the old value. Both are pervasive in Apple-framework code.

async / await, in three sentences

An async function may suspend; await marks each point where it might. While suspended, the thread is free to do other work — no callbacks, no completion handlers, and the code still reads top-to-bottom:

Sources/App/AppState.swiftlines 50–61
@MainActor
public func refreshData() async {
    isRefreshing = true
    defer { isRefreshing = false }        // runs on every exit path

    let graphResult = await apiClient.fetchPipelineGraph(serverConfig: activeServer)
    switch graphResult {
    case .success(let graph): self.graphData = graph
    case .failure:            self.graphData = MockGraphProvider.samplePipelineGraph()
    }
}

defer guarantees the spinner turns off however the function exits. await on an actor method means "hop to that actor's isolation, run, hop back" — which is exactly why refreshData must be @MainActor: the assignments to graphData drive the UI. Chapter 03 unpacks actors, Task, cancellation, and the Swift 6 data-race rules that shaped this file.

Four smaller things you'll see immediately

Conditional compilation

Sources/Views/PipelineVolumeView.swiftlines 16–30
#if os(visionOS)
RealityView { content in … }
#else
VStack(spacing: 20) { … }   // 2D placeholder so the package builds on macOS
#endif

#if is resolved at compile time, so the macOS build never even sees the RealityView. The same trick with #if canImport(UIKit) lets NodeEntity alias UIColor or NSColor to one name:

Sources/RealityKit/NodeEntity.swiftlines 3–9
#if canImport(UIKit)
import UIKit
typealias NodePlatformColor = UIColor
#elseif canImport(AppKit)
import AppKit
typealias NodePlatformColor = NSColor
#endif

Access control

Almost every declaration is marked public. For a single app target that's redundant — internal (the default) would compile identically. It's a habit from library code, and harmless; the one place it matters is that the SwiftPM target is built as a module the test target imports.

ARC and [weak self]

Sources/App/AppState.swiftlines 88–99
refreshTask = Task { [weak self] in
    while !Task.isCancelled {
        try? await Task.sleep(nanoseconds: UInt64((self?.autoRefreshInterval ?? 30.0) * 1_000_000_000))
        if self?.isAutoRefreshEnabled == true { await self?.refreshData() }
    }
}

Swift manages class instances with automatic reference counting. A long-lived closure that captures self strongly, while self also holds the closure (here via refreshTask), is a retain cycle — neither ever deallocates. [weak self] breaks it, at the cost of every use becoming optional. Note also 1_000_000_000: underscores are legal digit separators.

Operator overloading via simd

Sources/Services/ForceSimulation3D.swiftlines 125–126
node.velocity = (node.velocity + node.force) * damping
node.position += node.velocity

These are SIMD3<Float> values: + is component-wise, * by a scalar broadcasts. Vector maths reads like maths. Chapter 06 covers the rest of the simd surface this app uses.
